## 📖 Overview

After completing development work, branching, merging, and conflict resolution, it is important to ensure that the local Git repository is **clean and synchronized with the remote repository**.

A clean repository ensures that:

* No unnecessary branches remain.
* No unresolved changes are present.
* The local branch contains the latest remote changes.
* All required local commits have been pushed.
* The local and remote repositories are synchronized.

In this hands-on lab, the existing `GitDemo` repository will be reviewed and cleaned before synchronizing the final changes with the remote repository.

# 🧹 Part 4 — Clean Up Unnecessary Branches

If any old local branch still exists after being merged, delete it using:

```bash
git branch -d <branch-name>
```

For example:

```bash
git branch -d GitWork
```

or:

```bash
git branch -d GitNewBranch
```

If the branches were already deleted during previous hands-on exercises, no further action is required.

> **🛡️ Safe Delete**
> `git branch -d` protects against accidentally deleting a branch containing unmerged changes.

# 📡 Part 6 — Fetch Remote Information

Before pulling changes, retrieve the latest information from the remote repository:

```bash
git fetch origin
```

### What `git fetch` Does

| Operation                           | Performed? |
| :---------------------------------- | :--------: |
| Downloads remote commit information |      ✅     |
| Updates remote-tracking branches    |      ✅     |
| Modifies local working files        |      ❌     |
| Automatically merges changes        |      ❌     |

> **💡 Key Concept**
> `git fetch` retrieves remote information without modifying the current working branch.

# 🔄 Part 7 — Pull the Latest Remote Changes

Ensure that `main` is active:

```bash
git switch main
```

Pull the latest changes:

```bash

```

### Possible Output — Already Synchronized

```text

```

### Possible Output — New Changes Retrieved

```text
Updating a1b2c3d..d4e5f6g
Fast-forward
```

> **💡 Observation**
> `git pull` retrieves remote changes and integrates them into the currently checked-out branch.

# 🧪 Part 16 — Compare Local and Remote Branches

Check whether local `main` contains commits not available remotely:

```bash
git log origin/main..main --oneline
```

If no output is displayed, there are no unpushed local commits.

Now check whether the remote branch contains commits missing locally:

```bash
git log main..origin/main --oneline
```

If no output is displayed here as well, both branches are synchronized.

### Synchronization Check

| Command                               | No Output Means           |
| :------------------------------------ | :------------------------ |
| `git log origin/main..main --oneline` | No unpushed local commits |
| `git log main..origin/main --oneline` | No missing remote commits |

> **✅ Verification**
> If both commands return no commits, local `main` and `origin/main` point to synchronized histories.

---

# 🧹 Part 17 — Prune Stale Remote References

Remote branches that have already been deleted may sometimes remain visible as stale remote-tracking references.

Execute:

```bash
git fetch --prune
```

Then verify:

```bash
git branch -a
```

### Expected Final State

```text
* main
  remotes/origin/main
```

> **💡 Observation**
> The `--prune` option removes local references to remote branches that no longer exist.
