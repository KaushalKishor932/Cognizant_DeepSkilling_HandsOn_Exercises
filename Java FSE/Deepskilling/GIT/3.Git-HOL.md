## 📖 Overview

Branches are one of the most important features of **Git version control**. They allow developers to work on new features, bug fixes, or experiments independently without affecting the stable version of the project.

In this hands-on lab, a new branch named `GitNewBranch` will be created from the existing `GitDemo` repository. Changes will be made and committed on this branch, compared with the `main` branch, and finally merged back into `main`.

The exercise also demonstrates how to inspect the commit history and safely delete a branch after it has been merged.

# ➕ Part 3 — Create `GitNewBranch`

# 💾 Part 7 — Commit Changes on `GitNewBranch`

Commit the changes:

```bash
git commit -m "Add branch.txt in GitNewBranch"
```

<details>
<summary><strong>📤 Expected Output</strong></summary>

```text
1 file changed, 1 insertion(+)
create mode 100644 branch.txt
```

</details>

Verify the commit:

```bash
git log --oneline
```

### Example Output

```text
c3d4e5f Add branch.txt in GitNewBranch
b2c3d4e Add gitignore for log files and folders
a1b2c3d Add welcome.txt
```

> **✅ Result**
> The new commit belongs to `GitNewBranch` and has not yet been merged into `main`.

# 🔍 Part 8 — Compare the Branches

Git can compare the content and commits of different branches before performing a merge.

## 8.1 Compare `main` and `GitNewBranch`

Execute:

```bash
git diff main GitNewBranch
```

The output displays the changes introduced in `GitNewBranch` that are not currently present in `main`.

---

## 8.2 Compare Commit History

Execute:

```bash
git log main..GitNewBranch --oneline
```

### Example Output

```text
c3d4e5f Add branch.txt in GitNewBranch
```

> **💡 Observation**
> This command displays commits that exist in `GitNewBranch` but not in `main`.

---

## 8.3 View File-Level Differences

Execute:

```bash
git diff --stat main GitNewBranch
```

### Example Output

```text
branch.txt | 1 +
1 file changed, 1 insertion(+)
```

---

# 🖥️ Part 9 — Compare Using P4Merge (Optional)

If **P4Merge** is installed and configured as the Git diff tool, the differences can also be viewed graphically.

Configure P4Merge as the diff tool if required:

```bash
git config --global diff.tool p4merge
```

Launch the configured graphical diff tool:

```bash
git difftool main GitNewBranch
```

> **📝 Note**
> P4Merge is optional when reproducing the exercise on a modern environment. `git diff` provides the same branch comparison directly from Git Bash.

# 🔙 Part 10 — Switch Back to `main`

Before merging, switch to the branch that will **receive** the changes.

Execute:

```bash
git switch main
```

### Alternative

```bash
git checkout main
```

Verify:

```bash
git branch
```

### Expected Output

```text
  GitNewBranch
* main
```

> **💡 Key Concept**
> Since `GitNewBranch` needs to be merged **into `main`**, `main` must be the currently checked-out branch.

---

# 🔀 Part 11 — Merge `GitNewBranch` into `main`

Execute:

```bash
git merge GitNewBranch
```

A successful merge may produce output similar to:

```text
Updating b2c3d4e..c3d4e5f
Fast-forward
 branch.txt | 1 +
 1 file changed, 1 insertion(+)
 create mode 100644 branch.txt
```

> **✅ Result**
> The changes created in `GitNewBranch` are now available in the `main` branch.

# 📜 Part 13 — View Graphical Commit History

Git provides a graphical representation of branches and commits directly in the terminal.

Execute:

```bash
git log --oneline --graph --decorate --all
```

### Example Output

```text
* c3d4e5f (HEAD -> main, GitNewBranch) Add branch.txt in GitNewBranch
* b2c3d4e Add gitignore for log files and folders
* a1b2c3d Add welcome.txt
```

> **💡 Observation**
> Since this example can be merged using a fast-forward merge, both `main` and `GitNewBranch` may point to the same commit immediately after the merge.

---

# 🗑️ Part 14 — Delete the Merged Branch

Once the branch has been successfully merged, it is no longer required locally.

Execute:

```bash
git branch -d GitNewBranch
```

### Expected Output

```text
Deleted branch GitNewBranch
```

> **🛡️ Safe Delete**
> The lowercase `-d` option deletes a branch only when Git determines that its changes have already been merged.

---

## 14.1 Verify Branch Deletion

Execute:

```bash
git branch
```

### Expected Output

| Command                                | Purpose                                               |
| :------------------------------------- | :---------------------------------------------------- |

# 🔁 Branching & Merging Workflow

|      Stage      | Command                           | Result                          |
| :-------------: | :-------------------------------- | :------------------------------ |
|   **1. Check**  | `git status`                      | Verify clean repository         |
|  **2. Create**  | `git branch GitNewBranch`         | New branch created              |
|  **3. Switch**  | `git switch GitNewBranch`         | Feature branch activated        |
|  **4. Modify**  | Create `branch.txt`               | Independent change created      |
|   **5. Stage**  | `git add branch.txt`              | Change staged                   |
|  **6. Commit**  | `git commit`                      | Change stored in feature branch |
|  **7. Compare** | `git diff main GitNewBranch`      | Branch differences reviewed     |
|  **8. Switch**  | `git switch main`                 | Main branch activated           |
|   **9. Merge**  | `git merge GitNewBranch`          | Feature changes integrated      |
|  **10. Verify** | `git log --graph --oneline --all` | Merge history verified          |
| **11. Cleanup** | `git branch -d GitNewBranch`      | Feature branch removed          |
|   **12. Push**  | `git push origin main`            | Merged changes uploaded         |
