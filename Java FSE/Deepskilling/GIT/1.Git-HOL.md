# ⚙️ Part 1 — Git Configuration

## 1.1 Check Git Version

Open **Git Bash** and execute:

```bash
git --version
```

<details>
<summary><strong>📤 Expected Output</strong></summary>

```text
git version 2.xx.x.windows.x
```

</details>

> **💡 Observation**
> A valid version number confirms that Git is installed successfully and is accessible from the command line.

---

## 1.2 Configure Git Username

Configure the username that will be associated with Git commits:

```bash
git config --global user.name "Your Name"
```

### Example

```bash
git config --global user.name "Rahul Sharma"
```

> **📝 Note**
> The `--global` option applies the configuration to all Git repositories for the current user.

---

## 1.3 Configure Git Email Address

Configure the email address:

```bash
git config --global user.email "your_email@example.com"
```

### Example

```bash
git config --global user.email "rahul@gmail.com"
```

> **💡 Tip**
> Use the email address associated with your GitHub or GitLab account so that commits can be correctly linked to your profile.

---

## 1.4 Verify Git Configuration

Execute:

```bash
git config --global --list
```

<details>
<summary><strong>📤 Expected Output</strong></summary>

```text
user.name=Rahul Sharma
user.email=rahul@gmail.com
```

</details>

### Configuration Check

| Configuration | Expected Value                |
| :------------ | :---------------------------- |
| `user.name`   | Your Git username             |
| `user.email`  | Your registered email address |

---

# 📝 Part 2 — Configure Notepad++ as Git Editor

## 2.1 Verify Notepad++ Installation

Execute:

```bash
notepad++
```

If Notepad++ opens successfully, the application is accessible through the system PATH.

If the command is not recognized, add the following default installation directory to the **Windows Environment Variables**:

```text
C:\Program Files\Notepad++
```

---

## 2.2 Configure Notepad++ as the Default Editor

Execute:

```bash
git config --global core.editor "'C:/Program Files/Notepad++/notepad++.exe' -multiInst -nosession"
```

---

## 2.3 Verify Editor Configuration

Execute:

```bash
git config --global core.editor
```

<details>
<summary><strong>📤 Expected Output</strong></summary>

```text
'C:/Program Files/Notepad++/notepad++.exe' -multiInst -nosession
```

</details>

> **✅ Result**
> Notepad++ is now configured as the default text editor for Git operations.

---

# 📁 Part 3 — Create the Git Repository

## 3.1 Create the Project Directory

Create a new directory named `GitDemo`:

```bash
mkdir GitDemo
```

Navigate into the directory:

```bash
cd GitDemo
```

---

## 3.2 Initialize Git

Initialize the directory as a Git repository:

```bash
git init
```

<details>
<summary><strong>📤 Expected Output</strong></summary>

```text
Initialized empty Git repository in .../GitDemo/.git/
```

</details>

> **💡 Observation**
> Git creates a hidden `.git` directory containing the metadata and internal files required to manage version history.

---

## 3.3 Verify Repository Status

Execute:

```bash
git status
```

The repository is now ready to track files.

---

# 📄 Part 4 — Create & Track `welcome.txt`

## 4.1 Create the File

Create `welcome.txt` using Git Bash:

```bash
echo "Welcome to Git Hands-on Lab" > welcome.txt
```

### File Content

```text
Welcome to Git Hands-on Lab
```

Alternatively, create the file manually using **Notepad++** and save it inside the `GitDemo` directory.

---

## 4.2 Check Git Status

Execute:

```bash
git status
```

<details>
<summary><strong>📤 Expected Output</strong></summary>

```text
Untracked files:
  welcome.txt
```

</details>

### Current File State

| File          |   Git State  | Description                                     |
| :------------ | :----------: | :---------------------------------------------- |
| `welcome.txt` | 🔴 Untracked | Git detects the file but is not tracking it yet |

---

# 📦 Part 5 — Stage the File

## 5.1 Add `welcome.txt` to Staging

Execute:

```bash
git add welcome.txt
```

---

## 5.2 Verify the Staging Area

Execute:

```bash
git status
```

<details>
<summary><strong>📤 Expected Output</strong></summary>

```text
Changes to be committed:
  new file:   welcome.txt
```

</details>

### Updated File State

| File          | Previous State | Current State |
| :------------ | :------------: | :-----------: |
| `welcome.txt` |  🔴 Untracked  |   🟢 Staged   |

> **💡 Observation**
> `git add` moves the file changes into the **staging area**, preparing them for the next commit.

---

# 💾 Part 6 — Commit the Changes

## 6.1 Commit Using the Configured Editor

Execute:

```bash
git commit
```

Since Notepad++ was configured as the default Git editor, it will open automatically.

Enter the commit message:

```text
Add welcome.txt
```

Save the file and close Notepad++ to complete the commit.

---

## 6.2 Alternative: Commit Directly from Git Bash

The commit message can also be provided directly:

```bash
git commit -m "Add welcome.txt"
```

<details>
<summary><strong>📤 Expected Output</strong></summary>

```text
1 file changed, 1 insertion(+)
create mode 100644 welcome.txt
```

</details>

---

## 6.3 Verify Commit History

Execute:

```bash
git log --oneline
```

### Example Output

```text
a1b2c3d Add welcome.txt
```

| Value             | Meaning               |
| :---------------- | :-------------------- |
| `a1b2c3d`         | Shortened commit hash |
| `Add welcome.txt` | Commit message        |

> **✅ Result**
> `welcome.txt` has been successfully stored in the local Git repository.

---

# ☁️ Part 7 — Create a Remote Repository

Create a new remote repository named:

```text
GitDemo
```

The repository can be created on **GitHub** or **GitLab**.

### Recommended Repository Settings

For a clean initial push, do **not** initialize the remote repository with:

* README
* `.gitignore`
* License

After creating the repository, copy its HTTPS repository URL.

### Example

```text
https://github.com/yourusername/GitDemo.git
```

---

# 🔗 Part 8 — Connect Local & Remote Repositories

## 8.1 Add the Remote Repository

Execute:

```bash
git remote add origin https://github.com/yourusername/GitDemo.git
```

Replace `yourusername` with your actual username.

---

## 8.2 Verify the Remote

Execute:

```bash
git remote -v
```

<details>
<summary><strong>📤 Expected Output</strong></summary>

```text
origin  https://github.com/yourusername/GitDemo.git (fetch)
origin  https://github.com/yourusername/GitDemo.git (push)
```

</details>

### Remote Configuration

| Item            | Value    |
| :-------------- | :------- |
| **Remote Name** | `origin` |
| **Protocol**    | HTTPS    |
| **Fetch**       | Enabled  |
| **Push**        | Enabled  |

---

# 🌿 Part 9 — Configure the Main Branch

Rename the current branch to `main`:

```bash
git branch -M main
```

Verify the active branch:

```bash
git branch
```

### Expected Output

```text
* main
```

> **📝 Note**
> The `*` symbol identifies the currently active Git branch.

---

# 🚀 Part 10 — Push the Repository

Push the local `main` branch to the remote repository:

```bash
git push -u origin main
```

<details>
<summary><strong>📤 Expected Output</strong></summary>

```text
branch 'main' set up to track 'origin/main'.
```

</details>

> **💡 What does `-u` do?**
> The `-u` option establishes an upstream relationship between the local `main` branch and `origin/main`.

After the initial push, future commits can normally be uploaded using:

```bash
git push
```

---

# 🔄 Part 11 — Pull Changes from Remote

Retrieve the latest changes from the remote repository:

```bash
git pull origin main
```

If there are no new changes:

```text
Already up to date.
```

> **💡 Observation**
> `git pull` downloads the latest remote changes and integrates them into the current local branch.

---
